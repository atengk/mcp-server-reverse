# 0003. 基于 Capstone 的指令级相对寻址交叉引用（Xref）引擎与惰性索引

- **状态**: accepted

## 背景与问题

在现代 64 位二进制文件（尤其是 `x86_64` PE/ELF/Mach-O 与 `ARM64` 二进制）中，代码对字符串、全局变量及导入表桩函数的引用普遍采用**指令指针相对寻址**（如 `x86_64` 的 `lea rcx, [rip + disp32]` 或 `ARM64` 的 `adrp` + `add/ldr` 双指令组合），而非硬编码目标绝对虚拟地址。此外，若在一次逆向会话中每次调用 `find_xrefs` 都从头反汇编数 MB 的可执行节区，将造成严重的重复 CPU 开销与事件循环阻塞。

## 决策

在纯 Python 内核中构建基于 `capstone` 的静态交叉引用引擎与会话级惰性索引机制：

1. **指令级相对寻址与 `ARM64` 滑动窗口配对**：
   - **`x86_64`**：精确计算 `RIP-relative` 有效地址（`effective_va = insn.address + insn.size + disp`）；
   - **`ARM64`**：维护最近 4 条指令的寄存器页基址滑动窗口状态表，当识别到 `ADRP Xd, #page` 时记录页基址，遇到后续 `ADD Xn, Xd, #imm` 或 `LDR Xt, [Xd, #imm]` 时自动合成完整的 64 位精确目标虚拟地址（`page + imm`），同时兼容单条 `ADR` 相对寻址；
   - **直接控制流**：解析 `call`/`jmp`/`bl`/`b` 等直接分支指令的立即数目标 VA。
2. **数据段指针表扫描**：在数据节区（`.rdata`/`.data`/`.rodata`/`.got`）中按二进制位宽（32/64-bit）对齐扫描指向目标 VA 的绝对指针（`data_pointer`）。
3. **会话级惰性倒排索引与线程卸载防护**：
   - 首次在某 `BinarySession` 上调用 `find_xrefs` 时，通过 `asyncio.to_thread` 将全节区扫描卸载至工作线程，构建 `target_va -> List[XrefRecord]` 倒排索引并缓存在会话内存中，后续同一会话的 `find_xrefs` 查询直接 $O(1)$ 命中内存（`< 1ms`）；
   - 对单个可执行节区实施 `16MB` 默认扫描安全上限，超限时仅扫描前 `16MB` 并在响应 `summary` 中显式提示截断，防止百兆级巨型二进制阻塞服务。
4. **反汇编内联注释联动**：`disassemble` 复用同一套相对寻址解析逻辑，将命中的字符串字面量或导入/导出符号自动追加至指令末尾（`; -> 0x... "string"`）。
