# 0004. 控制流图抽取、写时复制内存虚拟打补丁与下一代威胁研判

- **状态**: accepted

## 背景与问题

随着 `v1.0.0` 正式发布，项目已完整实现基于纯 Python 与可选外部工具的基础静态逆向、特征常量检索与单级指令反汇编能力。但在进阶逆向分析、攻防对抗推演与高级威胁取证场景中，暴露出了如下深层结构性瓶颈：

1. **控制流抽象盲区与可视化诉求**：当前反汇编仅输出线性平铺指令流与单级交叉引用，缺乏函数内基本块（`BasicBlock`）边界切分与有向控制流图（CFG）拓扑。在面对复杂分支逻辑、嵌套循环或控制流平坦化等混淆技术时，大语言模型（LLM）难以构建清晰的执行路径心智模型，且无法直接获得直观的 `Mermaid` 流程图表达。
2. **假设性逆向（What-If Analysis）与物理磁盘保真铁律的冲突**：在漏洞验证与恶意代码分析中，逆向工程师与 Agent 经常需要探索假设性推演（例如：若将 `JZ` 反转为 `JNZ` 或 `NOP` 绕过反调试/序列号校验，后续控制流如何演化）。但在数字取证与逆向工程中，物理磁盘样本绝对不可变（保真只读）是基本红线，严禁在磁盘上修改原始样本或生成临时补丁文件污染宿主机。
3. **恶意代码规则研判与防御加固审计维度不足**：当前仅提供静态 IOC 提取与已知密码学常量匹配，无法消费安全团队庞大的工业级 YARA 规则资产；在节区熵值分析上，大节区内部局部加密/加壳 Payload 极易被整体香农熵稀释（大节区平均熵值不超 7.2，但局部 1KB~4KB 存在高熵加密块）；同时缺乏跨平台漏洞缓解机制（ASLR/DEP/CFG/CET/RELRO/Canary）的量化评级。
4. **轻量化与重型分析框架的依赖权衡**：引入动态微执行环境（如 Unicorn CPU 模拟单步解密）虽能辅助分析，但原生 C/C++ 动态库依赖沉重，在多平台分发时兼容性风险较高；必须在轻量化易用性与高级分析能力之间划定清晰的阶段性边界。

## 决策

1. **基于 Capstone 静态分支分析的基本块与控制流图构建 (`analyze_cfg`)**：
   - 纯 Python 零外部工具依赖，从指定函数入口点（或已识别的内部函数符号）开始线性遍历指令流；
   - 根据无条件跳转（`JMP`/`B`）、条件跳转（`JZ`/`JNZ`/`B.EQ` 等）、函数返回（`RET`）及跳转目标 VA 作为切分边界，将连续指令划分为单入口单出口的 `BasicBlock`；
   - 提取各基本块的起止 VA、指令序列、圈复杂度及后继边类型（`true_branch`、`false_branch`、`unconditional`），并直接格式化生成原生 `Mermaid` 流程图语法（`flowchart TD`），供 LLM 直观渲染与拓扑推演。
2. **会话级写时复制（COW）内存虚拟打补丁机制 (`patch_memory`)**：
   - 物理磁盘文件保持 100% 只读保真；在 `BinarySession` 实例中维护轻量级内存补丁覆写层（`PatchRecord` 条目集合）；
   - 在 `read_memory`、`disassemble` 及后续基于内存分析的 MCP Tools 查询时，动态无缝叠加覆写层；
   - 支持补丁列表查看（`list_patches`）与指定/全量原子回滚（Reset），杜绝临时文件产生与磁盘 I/O 污染。
3. **滑动窗口局部高熵块探测（`get_sections` 增强）**：
   - 在现有按节区计算全局香农熵的基础上，对大节区引入 1KB~4KB 步长的滑动窗口（Sliding Window Entropy）；
   - 探测节区内部局部的异常高熵连续块（$\ge 7.2$），精准捕捉隐藏在 `.text`、`.rdata` 或 `.data` 内部被整体稀释的加密 Shellcode 与加壳注入载荷。
4. **全平台漏洞缓解机制系统化审计与评分 (`audit_mitigations`)**：
   - 深度解析 PE 结构（DllCharacteristics 中的 `DYNAMIC_BASE`、`NX_COMPAT`、`GUARD_CF`、`CET_COMPAT` 及 SafeSEH 异常表）、ELF 结构（`GNU_STACK` 栈不可执行、`GNU_RELRO`/`BIND_NOW`、`DT_FLAGS_1 PIE`、Stack Canary 符号引用与 `FORTIFY_SOURCE`）以及 Mach-O 结构（PIE 标志、RESTRICT 段、Hardened Runtime 标志）；
   - 综合输出标准化的 `MitigationProfile` 实体，并生成 0~100 加固安全评分与利用难度评级。
5. **可选 YARA 规则匹配与优雅降级 (`scan_yara`)**：
   - 支持传入单条 YARA 规则文本或规则文件路径，对内存镜像或文件进行特征规则扫描，返回标准 `YaraMatch` 列表；
   - 采用可选依赖机制：若宿主机已安装 `yara-python` 则直接调用高性能 C 引擎；若未安装，提供结构化降级指引（推荐安装命令或提供内置轻量规则匹配器），保持不破坏核心运行环境。
6. **暂缓 CPU 微仿真**：
   - 明确将 Unicorn / QEMU 动态微执行环境（CPU 单步执行与寄存器模拟解密）推迟至 `v2.0` 重大版本，优先保证静态逆向与内存虚拟分析的极致稳定与轻量化。
