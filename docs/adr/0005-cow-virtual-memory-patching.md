# 0005. 会话级写时复制 (COW) 内存虚拟打补丁与只读保真机制

- **状态**: accepted

## 背景与问题

在二进制漏洞验证、CTF 攻防对抗推演与恶意代码分析场景中，逆向工程师与 Agent 经常需要探索假设性验证（What-If Analysis，例如：若将 `JZ` 反转为 `JNZ` 或替换为 `NOP` 绕过反调试或序列号校验，后续指令与函数控制流如何演化）。

但在数字取证（DFIR）与逆向工程中，**物理磁盘样本绝对不可变（保真只读）是不可逾越的红线**：
1. 严禁在磁盘上直接覆写修改原始样本，避免破坏数字取证哈希与证据有效性；
2. 严禁在磁盘生成临时补丁文件或副本，避免造成宿主机磁盘污染与未受控执行风险；
3. 需要支持在单个分析会话内随时查看已应用的补丁记录，并支持单项撤销或一键原子回滚恢复初始状态。

## 决策

在 `BinarySession` 会话层引入写时复制（Copy-On-Write / COW）虚拟内存补丁管理机制：

1. **会话级虚拟补丁覆写层 (`PatchRecord`)**：
   - 目标物理文件保持 100% 只读打开；
   - 在 `BinarySession` 实例内维护有序补丁字典 `_patches: dict[str, PatchRecord]`，记录补丁唯一标识符（`patch_id`）、目标虚拟地址、文件偏移、原始字节、替换字节与应用时间戳；
   - 补丁应用前执行十六进制格式校验、地址边界校验与只读节区合法性防御。
2. **读接口透明内存切片动态叠加**：
   - 底层 `read_bytes` / `read_memory`、静态反汇编 `disassemble`、基本块分析 `analyze_cfg` 以及 YARA 扫描引擎在访问二进制数据时，透明穿透并叠加当前会话已激活的补丁切片；
   - 使得打补丁操作无需重启会话，反汇编与控制流图能即时动态反映补丁生效后的逻辑走向。
3. **完备的补丁生命周期管理工具**：
   - `patch_memory`：原子应用指定十六进制补丁；
   - `list_patches`：列出当前会话所有激活补丁列表及前后字节对比；
   - `revert_patch`：支持传入 `patch_id` 撤回单项补丁，或缺省回滚全部补丁恢复原始净室镜像。
